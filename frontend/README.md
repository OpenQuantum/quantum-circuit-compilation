# Quantum Console

比赛前端在本仓库维护，由比赛 BFF 同源提供静态文件。HTML、CSS 与原生 ES modules 无构建依赖，Node 只用于检查和测试。

```sh
cd frontend
npm run check
npm test
```

浏览器入口为 BFF 根路径 `/`；静态资源使用 `/console/`。不要以文件 URL 或独立静态服务器打开：登录、Cookie、CSRF、聊天和下载都需要同源 BFF。

## 执行关系

- 登录和聊天走 `/api/human/v1`，复用 Star BFF 的用户会话、Agent 目录、对话与 Run。实际 Agent Runtime 独立部署。
- 实验、候选、包、日志和下载走 `/api/quantum/v1`。BFF 转发至 Quantum World 的受认证操作者 API。浏览器不持有 World 服务凭据或 Kaggle Token。
- 实验数据每 4 秒同步；对话消息每 2.5 秒同步，逐页读取真实持久消息。页面隐藏时暂停轮询，恢复时重新查询；不会自动重发输入或重启实验。
- Agent Run 的完成与电路实验完成分别展示。快速诊断结果标为不可提交；分数标为本地估算或配置参考值。
- 审批先展示包哈希，要求勾选人工确认并点击批准。上传需要另一个对话框中的显式确认。后端负责最终授权、哈希、有效期、最高分与一次性提交校验。
- 大文件通过按产物 ID 鉴权的下载链接获取，不经聊天消息传输。

`model.js` 集中处理安全文本输出、分数展示、审批按钮条件、产物链接和消息分页合并；`app.js` 管理会话、查询、交互与页面状态。所有实验与分数均来自服务端，不内置样例成绩。通信为 `demo` 模式时会持续展示明确提示。

首次登录用服务端配置的账号与访问口令。OIDC 环境使用统一登录链接。若看到 World 连接错误或 Agent 等待状态，需要先启动对应独立服务；这些状态不意味着实验已经执行。
