<h2>4. From the forum</h2>
<p>There is still no host answer in the window to the three validity questions from yesterday. Two new topics and one
reply add to them.</p>
<ul>
<li><strong>R resets in place of uncomputation</strong>
(<a href="https://www.kaggle.com/competitions/google-verifiable-quantum-circuit-compilation/discussion/755302" target="_blank">755302</a>,
Jyoti Negi; reply by Hassan Mohamed).<ul>
<li>The problem: the verifiers run only basis-state inputs. A circuit that clears input-dependent scratch with R would
therefore pass. On a superposition input it would no longer implement the phase oracle.</li>
<li>Hassan Mohamed's reply notes that the uncompute half is about half of all Toffolis in the public DQI decoders. A
ruling before the 20 Nov milestone would change the cost scale for everyone.</li>
<li>Related: <a href="https://www.kaggle.com/competitions/google-verifiable-quantum-circuit-compilation/discussion/755427" target="_blank">755427</a>
(Pizzaboi) asks about off-path loader behaviour.</li></ul></li>
<li><strong>What counts as a generator?</strong>
(<a href="https://www.kaggle.com/competitions/google-verifiable-quantum-circuit-compilation/discussion/755488" target="_blank">755488</a>,
Toluwalase Olufemi). The question follows on from the hosts' answer in
<a href="https://www.kaggle.com/competitions/google-verifiable-quantum-circuit-compilation/discussion/752010" target="_blank">752010</a>. Can a
prize generator start from a hash-pinned public Apache-2.0 compiled circuit and transform it, or must it build every
circuit from source? This matters because most of today's records are edits of compiled files.</li>
<li><strong>Training on rented GPUs</strong>
(<a href="https://www.kaggle.com/competitions/google-verifiable-quantum-circuit-compilation/discussion/755643" target="_blank">755643</a>,
rikirinjani). The question is whether rule B.4(b) allows running the starter-kit trainer on a private rented A100,
with T4 versus A100 throughput quoted. No host answer yet.</li>
<li><strong>Steering agents</strong>
(<a href="https://www.kaggle.com/competitions/google-verifiable-quantum-circuit-compilation/discussion/755303" target="_blank">755303</a>,
uctpexx123). The question is how to keep agent loops from converging on small local edits. Agniv Banerjee suggests a
map, or DAG, of directions instead of a single propose–verify loop.<ul>
<li>Our two cents: we keep a ledger of every closed idea with the reason it closed, and when it would be worth
reopening. That makes "this formulation failed" a separate record from "this direction is dead". The public form is
our <a href="https://www.kaggle.com/datasets/manwithacat/vqcc-chemistry-negative-results" target="_blank">negative-results dataset</a>.</li></ul></li>
<li><strong>Grid search versus exact angles</strong>
(<a href="https://www.kaggle.com/competitions/google-verifiable-quantum-circuit-compilation/discussion/755525" target="_blank">755525</a>, Pablo
Diego Pereira). Right-multiplying a factor by an orthogonal matrix leaves the reconstruction unchanged but moves the
column L1 norms. The minimum sits on the kinks where entries cross zero, which a fixed grid misses.<ul>
<li>This matches what we found refitting weights: the published fits sit at those kinks. Our public
<a href="https://doi.org/10.5281/zenodo.23930466" target="_blank">refit write-up</a> has the column-gauge step.</li></ul></li>
<li><strong>DQI on real hardware</strong>
(<a href="https://www.kaggle.com/competitions/google-verifiable-quantum-circuit-compilation/discussion/755738" target="_blank">755738</a>, Peter
Babulik). A small-field DQI demonstration run on IBM's Heron processor, which is outside the scored task.</li>
</ul>

<h2>5. Tools and notes from us</h2>
<ul>
<li><strong>Circuits dataset and blend notebook.</strong> The
<a href="https://www.kaggle.com/datasets/manwithacat/vqcc-apache-public-circuits" target="_blank">circuits dataset</a> went through several
versions since yesterday's post, now v98, with 312 credited circuits in <code>manifest.csv</code>. The
<a href="https://www.kaggle.com/code/manwithacat/the-real-150k-was-the-friends-we-made" target="_blank">blend notebook</a> re-ran after each
record, now v109.</li>
<li><strong>How each new chemistry file is described.</strong> Each one is classified against the published parts: weights only,
loaders only, both, or an identical copy. Its loaders are then recombined with every compatible set of weights. This
is how the dataset can say "Agniv's weights on Ayodeji's loaders". Today the recombination never beat the best single
public file by more than the noise threshold.</li>
<li><strong>Refits of today's public weights.</strong> Running our public
<a href="https://doi.org/10.5281/zenodo.23930466" target="_blank"><code>dfthc_refit</code></a> tool on today's public weights gained at most 1.5 × 10^-4.
This is a measured null: those weights are already at the refit optimum.</li>
</ul>
<h2>6. What we think it means (opinion)</h2>
<ul>
<li><strong>Chemistry is becoming a loader problem again.</strong> Ayodeji's 508-Toffoli loader saving on an older table beat a
table with a lower λ_eff. We expect the next records to come from loaders for the C = 45 and C = 39 tables, and
perhaps from a table chosen for its loader cost rather than its λ_eff alone.</li>
<li><strong>The public plateau is now at the silver line.</strong> Small public steps (0.1–0.2% a day) move hundreds of ranks,
while the top ten sit 8–17% higher on work that is not public.</li>
<li><strong>The rules questions matter more than any single circuit.</strong> These are the R-reset, off-path loader and generator
questions in section 4. A ruling on any of them would change how much of today's frontier is usable.</li>
</ul>
